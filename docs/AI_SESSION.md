# История работы с AI

Дата: 20.10.2026, часовой пояс пользователя — Europe/Moscow. Среда: Codex desktop, Windows, PowerShell. Один AI-чат, без делегирования другим агентам.

## Исходное сообщение пользователя

> Разработай для меня готовый к сдаче MVP сервиса форм для карьерной платформы студентов. Это тестовое задание с ориентиром около двух часов работы, поэтому выбери небольшой, продуманный набор функций и доведи основной сценарий до рабочего состояния.
>
> **Проблема:** менеджеры без технических навыков вынуждены заказывать формы у разработчиков, а студенты часто бросают заполнение. Нужен сервис, в котором менеджер самостоятельно создаёт форму отклика на стажировку или мероприятие, публикует её по ссылке и просматривает ответы.
>
> **Обязательный сценарий:**
>
> 1. Менеджер открывает `/admin` без авторизации.
> 2. Создаёт форму: задаёт название, описание и поля, отмечает обязательные вопросы.
> 3. Публикует форму и получает уникальную ссылку.
> 4. Студент открывает ссылку, заполняет форму и отправляет ответы.
> 5. Менеджер видит полученные отклики в административной панели.
>
> Для конструктора достаточно нескольких полезных типов полей: короткий текст, длинный текст, email и выбор одного варианта. Предусмотри редактирование, удаление и изменение порядка вопросов. Продумай, как изменения опубликованной формы влияют на уже полученные ответы.
>
> Сделай понятный интерфейс на русском языке, адаптированный для телефона и компьютера. Добавь валидацию, состояния загрузки, пустые состояния и подтверждение успешной отправки. Сохраняй введённые студентом данные при ошибке отправки.
>
> Чтобы затронуть проблему незавершённых откликов, при наличии времени добавь простую аналитику: открытия формы, начала заполнения и успешные отправки. Чётко опиши способ подсчёта и ограничения этих показателей. Основной рабочий сценарий важнее аналитики и дополнительных функций.
>
> **Обязательные технические требования:**
>
> - Node.js 20 или новее.
> - Запуск из корня репозитория строго двумя командами: `npm install`, затем `npm start`.
> - После запуска приложение доступно по адресу `http://localhost:3000`.
> - Порт можно изменить через переменную окружения `PORT`.
> - Админка находится по адресу `/admin`, без авторизации.
> - Публичная форма доступна по уникальной ссылке, созданной в админке.
> - Никаких API-ключей, облачных сервисов, внешних API или отдельно устанавливаемых СУБД.
> - Данные хранятся внутри проекта и сохраняются после перезапуска приложения. Используй SQLite или JSON-файл.
> - Если нужна сборка или инициализация хранилища, они выполняются автоматически в рамках указанных команд.
> - Итоговый код должен находиться в публичном репозитории GitHub.
>
> Самостоятельно выбери простой и надёжный стек. Не усложняй архитектуру и не добавляй функции, которые мешают качественно завершить MVP. При неоднозначностях принимай разумные решения и кратко фиксируй их.
>
> Подготовь README с инструкцией запуска, описанием возможностей, архитектурных решений, ограничений и возможных следующих шагов. Сохрани историю работы с AI и добавь `AI_USAGE.md` с описанием использованных инструментов, выполненных с их помощью задач и проведённых проверок. Не выдумывай историю использования AI.
>
> Перед сдачей проверь запуск с чистой установкой зависимостей, работу `PORT`, сохранение данных после перезапуска и полный сценарий от создания формы до просмотра отклика. Исправь обнаруженные ошибки.
>
> Создай публичный репозиторий GitHub и опубликуй готовое решение, если доступ к моему GitHub уже настроен. Если доступа нет, подготовь проект полностью и сообщи, какое действие нужно от меня для публикации. Не считай задание завершённым до проверки запуска.
>
> После успешной публикации в финальном ответе пришли только ссылку на публичный репозиторий.

## Ход работы

1. AI сообщил, что проверит среду, затем реализует локальный MVP и обязательный сценарий. Проверены Node.js `v26.5.0`, npm `12.0.2`, Git `2.55.0.windows.4`. `gh` не установлен. В рабочей папке были посторонние проекты; для задания создан отдельный каталог `career-forms-mvp`.
2. Прочитаны навыки Sites, локального предпросмотра и вводная инструкция Computer Use. Требование пользователя о самостоятельном Node.js-приложении принято приоритетным; облачные инструменты Sites не использовались.
3. Приняты решения: встроенный Node.js HTTP-сервер без npm-зависимостей; vanilla JS/CSS; JSON с атомарной записью; отдельные черновик и публикации; снимки вопросов в откликах; UUID для идентификаторов формы, вопросов, сессии и повторяемой отправки.
4. Созданы `server.js`, манифест npm, статическая оболочка, favicon. Реализованы API создания/сохранения/публикации, валидация, отклики, аналитические события, защита от устаревшей ревизии и записи с другого Origin.
5. Созданы интерфейсы списка форм, пустого состояния, конструктора, предпросмотра, публикации, откликов и студенческой формы. Добавлены загрузка, ошибки, подтверждение удаления, прогресс, локальный черновик, повтор отправки и экран успеха.
