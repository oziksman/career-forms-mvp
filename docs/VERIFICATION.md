Дата: **20.10.2026**. Локальная среда: Windows, Node.js **v26.5.0** (соответствует требованию Node.js ≥20), npm **12.0.2**, Git **2.55.0.windows.4**. ## Автоматические проверки — успешно

Команды:

```sh
node --check server.js
node --check public/app.js
npm test
```

Результат последнего прогона:

```text
tests 10
pass 10
fail 0
cancelled 0
skipped 0
todo 0
```

Состав проверок:

1. HTTP: админка, ресурсы, редирект, 404 и защитные заголовки.
2. Создание черновика, отсутствие публичного доступа до публикации, четыре типа полей.
3. Серверная валидация обязательности, email, варианта и длины ответа; ошибочные ответы не записываются.
4. Конкурентный повтор одной отправки даёт один отклик; события сессии дедуплицируются.
5. Перестановка, удаление и переименование не меняют старые снимки; открытая старая версия принимает ответ.
6. Конкурентное сохранение с одной ревизией даёт один 200 и один 409; устаревшая публикация отклоняется.
7. Невалидные схемы, повтор UUID вопроса, пустая публикация, неизвестная версия, чужой Origin и повреждённое тело JSON отклоняются.
8. Реальный перезапуск на другом `PORT` сохраняет формы, версии и отклики.
9–10. Верхнеуровневый жизненный цикл и отдельный запуск с повреждённым JSON: приложение завершается, исходное содержимое остаётся нетронутым. Нумерация Node включает родительский тест, поэтому итоговая сводка показывает 10, а не число отдельных assert.

## Браузер: полный сценарий — успешно

Проверено в реальном Chromium через браузер Codex:

- Пустая админка, создание с нуля, название и описание.
- Добавление короткого и длинного текста, email и выбора одного варианта.
- Обязательные вопросы, редактирование вариантов, перестановка вверх/вниз.
- Публикация версии 1 и получение уникальной ссылки.
- Пустая отправка подсвечивает три обязательных вопроса и переводит фокус на первый.
- Неверный email показывает ошибку, сохраняя остальные ответы.
- При выключенном сервере отправка показывает сетевую ошибку и сохраняет ответы.
- После включения сервера и перезагрузки той же вкладки восстанавливаются все четыре ответа, выбранный вариант и прогресс.
- Повторная отправка успешна; экран подтверждения сообщает о получении отклика.
- Менеджер видит один отклик и все четыре ответа. Аналитика: 1 открытие, 1 начало, 1 отправка.
- Удаление четвёртого вопроса требует подтверждения. Публикация создаёт версию 2; исходный отклик остаётся версией 1 с удалённым вопросом и ответом.
- Визуально проверены десктопная админка, публичная форма, мобильные форма/подтверждение/админка. Проверка мобильного viewport выполнялась с настройкой 390×844; измеренная ширина контента не превышала ширину viewport. Временная настройка сброшена.

Это проверка основного пользовательского сценария и выбранных ошибок, а не полная матрица браузеров, нагрузочный тест или аудит доступности.

## Исправления по результатам

- Windows: `fsync` требует подходящий дескриптор; временный файл открывается в `r+`.
- Проверка актуальной `revision` перенесена после получения тела запроса; исключена перезапись из конкурентной вкладки.
- Корректно восстанавливаются disabled-состояния крайних стрелок после сохранения.
- Диалогам добавлены доступные заголовок и описание.

Тестовые ответы вымышленные. Рабочие JSON-файлы исключены из Git и публикации. Публикация GitHub фиксируется в журнале отдельно от работоспособности локального приложения.
