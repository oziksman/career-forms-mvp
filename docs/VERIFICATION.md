## Исправление лимита размера запроса — 20.10.2026

Регрессия воспроизведена до изменения кода: форма с 30 обязательными `textarea` и 5000 ASCII-символов в каждом ответе отправляла JSON размером 151 387 байт и получала 413 при ожидаемом 200.

Общий лимит увеличен с 128 КиБ до 1 МиБ. Верхняя оценка допустимых ответов при JSON-экранировании: 30 × 5000 × 6 = 900 000 байт; оставшегося места достаточно для UUID-ключей и метаданных. Лимит отдельного поля остался 5000 единиц UTF-16, согласованно с браузерным `maxlength`.

Добавленный интеграционный тест создаёт и публикует максимальную форму, последовательно отправляет 30 × 5000 ASCII-символов, кириллических, трёхбайтовых UTF-8-символов и экранируемых управляющих символов. Для каждого набора проверяются 200 и точное сохранение всех ответов через API и на диске. Дополнительно проверены 422 для одного ответа длиной 5001, 413 для тела больше 1 МиБ и неизменное число откликов после этих отказов.

Выполнены отдельный прогон регрессии, полный `npm test` и `git diff --check`. Результат этого прогона: **11 tests, 11 pass, 0 fail**.

## Аудит согласованности UI, API и README — 20.10.2026

Исправлены дополнительные расхождения:

- Пустые строки в редакторе больше не занимают один из 20 вариантов. Число проверяется после их исключения, дубликаты — после удаления пробелов.
- В конструкторе проверяются 160 единиц для каждого варианта и число вариантов, вместо обрезания редактора по суммарным 3220 единицам. Предпросмотр также исключает пустые строки.
- Конструктор и публичная форма используют те же функции проверки, что сервер: длина всех полей, обязательность, допустимый вариант, простой формат email и однострочность CR/LF. Название, описание и ответы нормализуются одинаково.
- При сохранении опубликованной формы браузер отправляет только черновик с ревизией, без копии публикации и статистики. Для максимальной схемы JSON из админского ответа больше 1 МиБ, а корректный запрос сохранения укладывается в лимит.
- Текст интерфейса и README уточняют, что новая версия создаётся при публикации изменений; повтор без изменений не создаёт дополнительную версию. Документированы неполные черновики, единицы UTF-16 и правила пробелов.

Общие правила вынесены в один модуль, который обслуживается как JS-ресурс и импортируется Node.js и браузером. HTTP-тесты проверяют границы названия 160, описания 2000, вопроса 240, варианта 160, количества вариантов 20 и вопросов 30, все четыре типа ответов, emoji, длину до обрезания пробелов, пустые строки, дубликаты, CR/LF, типы значений, сохранение и публикацию максимальной схемы. Для ошибок сравниваются результат клиентской функции и HTTP-ответ сервера. Проверено, что пустой необязательный email принимается, а непустой неверный — отклоняется.

Три теста UI исполняют **реальный `public/app.js`** в Node `vm` с минимальными заглушками DOM и fetch. Проверены отрисованные `maxlength`, отключение добавления 31-го вопроса, нормализация предпросмотра, отказ до сетевого запроса для неверного варианта/восстановленного длинного ответа и состав запроса сохранения большой опубликованной формы. Эти тесты не подменяются заявлением о полноценном браузерном прогоне.

В реальном браузере отдельно пройдены создание формы, ошибки для варианта длиной 161 и списка из 21, публикация 20 вариантов с пустыми строками, ошибка обязательного выбора, успешная отправка «Вариант 20» и чтение точного ответа менеджером. ## Повторная сверка с требованиями — 20.10.2026

Проверка начата с коммита `15404cd`, где общий контракт уже присутствовал. Дополнительно исправлены ошибки обработки состояний и совместимости:

- Один `requestId` возвращает прежний успех только для той же версии и тех же нормализованных ответов. Изменённый повтор получает 409; прежний отклик остаётся неизменным, дубликат не появляется. Некорректные ответы также проходят валидацию и получают 422.
- Исторические опубликованные схемы не проверяются заново при чтении по более строгим правилам конструктора. Регрессионный тест воспроизвёл прежний 422 при GET старой формы. Теперь её можно прочитать, сохранить исправленный черновик, опубликовать версию 2 и принять ответ на исходный вариант версии 1. Снимок и ответ проверяются без преобразования. Создание новых многострочных вариантов всё так же запрещено.
- При успешном сохранении черновика и сбое публикации статус показывает сохранённый черновик, а ошибка сообщает, что публикацию не удалось подтвердить. README больше не обещает, что при любой сетевой ошибке сервер ничего не записал.
- Поздний ответ загрузки откликов не заменяет конструктор после смены вкладки. На время отправки заблокированы переходы внутри приложения. Проверены внутренние переходы после создания пустой формы и шаблона, чтобы блокировка не нарушала основной сценарий.
- Клиентский тест ответа с конфликтом проверяет отсутствие ложного подтверждения, сохранение изменённого текста в памяти и sessionStorage и повторную доступность кнопки отправки.
